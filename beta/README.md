# Gaia isolated membership beta

This is the password-protected test runtime used beside the existing app. It is
not a production billing server. Test purchases, CRM operations, approvals and
member records are fictional and cannot invoke Stripe, GHL or a paid AI model.
The app APIs and native beta pages read the same workspace membership, wallet,
course grants and lesson progress. The transactional Membership 2.0 service is
in `../membership-service`; its real-provider rollout remains separately gated.

## Run deterministic tests

Node 20 or newer; no install is needed for beta unit tests:

```
npm --prefix beta test
npm --prefix beta run check
```

Tests explicitly use `test-fixtures/academy-manifest.json`, a **synthetic**
catalog without real video links. It is not a provider integration result.
A missing runtime manifest yields no original courses, not a fictional fallback.

## Existing test deployment

Run `beta-server.mjs` only with the existing isolated loopback services: web
8798, staging proxy 8797, and demo-filtered Control Center 8799. It listens on
127.0.0.1:8800. No proxy route targets production. The existing deployment keeps
these modules together in its beta runtime directory.

Configure `BETA_ENV_FILE` and `STAGING_PROXY_ENV_FILE` with private env-file paths.
The first needs `BETA_PASSWORD` and `BETA_COOKIE_SECRET` (20+ characters each).
The second supplies fixture and console credentials; never commit either file.
Optional `BETA_WORKSPACE_DIR` and `BETA_MARK_FILE` override workspace/brand paths.
`BETA_ACADEMY_MANIFEST` points to the authorized private course catalog snapshot;
otherwise `./staging-proxy/data/academy-manifest.json` is used. Neither real course
sources nor learner records belong in this repository.

Deploy `assets/beta-jakarta.ttf` into the isolated web copy's assets directory.
Retain existing Gaia artwork and Phosphor icons from that copy. `beta-media/`
contains the silent orientation clip and captions. The scripts in `beta-tests/`
include server-specific browser/security checks; read their environment and port
requirements before running them. They must never target production.

## Access and privacy

- One signed workspace owns a unique fictional member identity.
- Effective paid benefits require active access before its paid/grace deadline.
- Explicit `beta_manual` course grants are generated by the local provider fixture
  from the configured benefit map. Production still requires GHL-synchronized or
  manual grants; a membership label by itself grants no production course.
- Lesson completion, saved native video positions and Personal Path state persist
  only in that workspace. Sign-out blocks reads/writes; reset clears the data.
- Native video positions save on pause and every 15 seconds; embedded provider
  players do not expose playback position to this runtime.
- Provider-approved recommendations are tested in `staging-proxy/test/`; the beta
  does not pretend to have a real partner link. The Personal Path uses the same
  production rule engine with non-clinical workspace signals.

Do not merge this branch or deploy production without the owner's approval.
